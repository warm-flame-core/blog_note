# 引言

上一篇把 STM32F103ZET6 这个名字从头到尾拆了一遍：ST 是意法半导体，M 是微控制器，32 是 32 位，F1 是主流系列，103 是子系列，Z 是 144 个引脚，E 是 512 KB Flash，T 是 LQFP 封装，6 是工业级温度范围。名字是读懂了，但那终究是纸面上的东西。

真正把这颗芯片拿到手上的时候，我遇到的是另一堆问题：它四边伸出来的那些金属脚，到底从哪一根开始数？为什么有的脚叫 PA0，有的脚叫 VDD？接错了会怎么样？程序又是怎么从电脑进去芯片的？

这篇就是把这些问题一次理清楚。范围限于芯片外形、引脚体系，以及把开发环境搭起来要走的流程，偏概念，动手的结果留给后面。

## 一、STM32 的由来与 F103 的定位

STM32 之前，学嵌入式的人大多从 51 单片机起步。51 是 8 位的，诞生于上世纪 70 年代，结构简单、容易上手，最省事的一点是它能通过串口直接下载程序，不买仿真器也能玩起来。所以直到现在，很多学校的嵌入式课还在用它。

但市场不等人。产品对成本极度敏感，对 MCU 的要求却一路往上走：功能要多、功耗要低、最好还能同时干几件事。8 位的老架构在这些要求面前越来越吃力。

ARM 在这个时候拿出了基于 ARMv7 架构的 32 位内核 Cortex-M3，意法半导体跟着推出了基于这颗内核的 MCU，也就是 STM32。它能起来靠的是三样东西：产品线铺得够宽、性价比够高、配套的库开发方式够省事。程序员不用再对着几百页手册逐位配寄存器，调一个函数就能初始化外设。F103 是这条产品线里最经典的一颗，累计出货十几亿片，工业级可靠性、-40℃ 到 85℃ 的温度范围、各路外设都在，属于那种资料随手就能搜到的"国民级"芯片。

名字的拆解过程不重复了，上篇已经逐字段列过表（[[STM32/STM32入门概念篇——从嵌入式、MCU到命名规则与开发环境]]）。这篇直接从实物开始。

## 二、LQFP144 封装

拿到芯片第一眼，它是个黑色的小方块，四条边整整齐齐伸出一片金属脚。

![[STM32/attachments/STM32F103ZET6实拍.png|STM32F103ZET6 芯片正面，丝印上的型号清晰可读]]

那些金属脚就是引脚，也叫针脚、pin，是芯片和外部电路之间的通道。所有的信号进出都要走这里。

芯片想要工作就得焊到电路板上，电路板上有对应的焊盘。**封装**描述的就是这层对应关系：芯片的外形如何、引脚按什么排布、焊盘要画成什么样。封装决定了电子元件的物理形状必须和焊盘匹配得上，否则焊不上去。

型号最后第二位的 T 就是封装代码。STM32 常见的封装有这三种：

| 字母 | 缩写 | 英文全称 | 中文 | 手焊难度 |
| --- | --- | --- | --- | --- |
| T | LQFP | Low-profile Quad Flat Package | 薄型四边扁平封装 | 低，引脚露在外面 |
| H | BGA | Ball Grid Array | 球栅阵列封装 | 高，焊点在芯片底部 |
| U | VFQFPN | Very Thin Fine-pitch Quad Flat No-lead Package | 超薄细间距四边扁平无引脚封装 | 高，焊盘在芯片底部 |

这套字母映射是经典 F1 系列的约定，其他系列会在型号末尾追加后缀字段，碰到没见过的组合以官方数据手册为准。

LQFP 的引脚从四条边水平伸出来，肉眼看得见、烙铁够得着，飞线也能挂上去。BGA 完全不同，它的"引脚"是一颗颗焊球排在芯片底下，焊完之后看不见任何引脚，得靠回流焊加 X 光检查，个人条件下基本没法返修。VFQFPN 也是把焊盘藏到底部，比 LQFP 省面积，但同样不适合手焊。

入门阶段选 LQFP144 是有道理的：这颗芯片有 144 个引脚，每条边 36 个，间距很小，但它至少还给了手工焊的可能。

## 三、引脚的编号规则

拿到实物先找标记。芯片正面有一个实心的小圆点，它标记的那一端就是 1 号引脚的位置。

![[STM32/attachments/LQFP144封装尺寸.png|封装图上标注的 1 号引脚位置]]

规则很简单：从离圆点最近的那个引脚开始算 1 号，沿着逆时针方向一路数到 144。四条边各 36 个，正好对上 Z 这个字段。

把整个引脚关系铺开看是这样：

![[STM32/attachments/STM32F103ZET6引脚布局.png|LQFP144 封装的 144 个引脚全景图]]

这类信息不是我猜的，都能在《数据手册》里查到。引脚相关内容在 Pinouts and pin description（引脚定义）这一章，封装尺寸在 6.4 LQFP144 package information。中文版数据手册有些章节不全，看英文版更稳妥。

电子元件的种类太多，参数和性能又千差万别，厂商干脆把自家产品的所有细节写进一本数据手册。参数本身是记不完的，知道去哪查才算站得住脚。

## 四、物理编号与功能名

数引脚用的是 1 到 144 这串数字，它是**物理编号**，描述这根针长在芯片的哪个位置。焊板子、查故障的时候关心的是这个。

写代码时用的是另一套：**功能名**，比如 PA0、PB12、VDD、NRST。它描述这根针是干什么活的。两者是一一对应的关系，只是视角不同。

打个比方：一间教室里，每个座位有"第几排第几列"的位置编号，也有坐在那个位置上的人名。你想找某个同学具体坐在哪，得先知道座位号；你想叫某人回答问题，喊的是名字。芯片上"编号"对应座位号，"功能名"对应人名。

还有一层：一个物理引脚可以承担多个功能。PA9 既是最普通的输入输出口，也可以被配置成串口的发送脚。到底扮演哪个角色，由软件决定。这里先知道有复用这回事，具体怎么配留到讲外设的时候。

数据手册里那张很长的引脚表，本质上就是把位置编号和功能名对照起来的一张表。

## 五、特殊功能引脚与普通引脚

144 个引脚按性质可以分成截然不同的两类。

### 可编程的普通引脚

先按字母分组，再按数字编号：

| 分组 | 引脚 | 数量 |
| --- | --- | --- |
| PA | PA0 ~ PA15 | 16 |
| PB | PB0 ~ PB15 | 16 |
| PC | PC0 ~ PC15 | 16 |
| PD | PD0 ~ PD15 | 16 |
| PE | PE0 ~ PE15 | 16 |
| PF | PF0 ~ PF15 | 16 |
| PG | PG0 ~ PG15 | 16 |

七组乘以十六，一共 112 个。它们就是 GPIO（General Purpose Input/Output，通用输入输出），功能完全由软件决定：可以配成输入去读按键的高低电平，配成输出去点亮 LED，或者复用成串口、SPI（Serial Peripheral Interface，串行外设接口）、定时器 PWM（Pulse Width Modulation，脉宽调制）、ADC（模数转换器）采样通道这类外设功能。后面写的代码，绝大部分逻辑都是在跟这些引脚打交道。

### 硬件固定的特殊功能引脚

剩下的 32 个引脚不做这些事。它们的功能在芯片出厂时就固定了，软件没法改写，必须按数据手册的要求接到正确的地方，芯片才能跑起来。

这张图把它们的位置标了出来：

![[STM32/attachments/STM32F103ZET6特殊功能引脚.png|用彩色框标出特殊功能引脚的分布]]

逐个捋一遍常见的几个：

**VDD 与 VSS** 是电源。VDD 里的 D 指 MOS 管的漏极（Drain），代表芯片内部逻辑电路的工作电压，在 STM32F103 上通常接 3.3V；VSS 里的 S 指源极（Source），是电路的公共参考地，接到 GND。一对还不止一组，芯片为了保证各处的供电稳定，会多组引出，每组旁边一般还要放退耦电容。这类电源地引脚在剩下的 32 个里占了不小的比例，除了一组又一组的 VDD/VSS，还单独准备了一组 VDDA/VSSA，专门给芯片内部的模拟部分供电。

至于为什么单片机供电的高电平普遍是 3.3V，这是芯片制造工艺进步和低功耗需求共同演化出来的一个行业标准：早年的 5V 随着晶体管越做越小，栅极能承受的电压一路降下来，3.3V 既保证了足够的抗干扰裕度，又显著降低了功耗。

**NRST** 是复位引脚，让单片机强制回到初始状态，效果和电脑上"重启一下试试"是一样的。名字里那个 N 代表 Negative 或 Not，强调它是低电平有效：引脚为低电平（接地）时芯片处于复位状态，为高电平（3.3V）时正常运行。所以开发板上这个引脚通常接一个按键，按键另一端接地，按下去就复位。烧录完成之后按一下让程序重新跑起来，用的就是它。

**VBAT** 是备用电池引脚。主电源掉电之后，它接的纽扣电池会接管，专门喂给 RTC（Real Time Clock，实时时钟）和备份寄存器，保证时间不断、关键数据不丢。要注意的是它只维持这两样东西，芯片其余部分已经停了。这跟电脑拔掉电源之后，主板上那颗电池的作用几乎一模一样：机器没法开机，但下次开机时间还是准的。

**BOOT0** 决定启动模式，也就是芯片复位之后从哪开始执行指令。

| BOOT0 | 行为 | 什么时候用 |
| --- | --- | --- |
| 接 GND | 运行已经烧录进 Flash 的用户程序 | 绝大多数时候，包括正常调试 |
| 接 3.3V | 进入芯片内部固化的 Bootloader，等待串口下载 | 仿真器烧不进去时的救急通道 |

Bootloader 是意法半导体在生产时固化到芯片系统存储器里的一段程序，改不掉也删不了，专门负责通过串口把固件写进去。开发板上 BOOT0 的默认做法是接地。这里还有个 BOOT1，实际项目中通常直接焊死接地，永远给低电平，所以日常只需要关心 BOOT0。

顺便把 NRST 和 BOOT0 分开说清楚，这两个最容易搞混。NRST 管的是"要不要从头开始跑"，不改变启动来源；BOOT0 管的是"重新跑的时候跑谁"。用电脑类比：NRST 相当于按下重启键，BOOT0 相当于开机时按 F2 选择从哪块盘启动。

另外几个：OSC_IN 和 OSC_OUT 用来外接石英晶振，给芯片提供更准的时钟基准；VREF+ 和 VREF- 是 ADC 转换的参考电压输入，只有在引脚数较多的封装上才会引出来，144 脚这颗是有的，参考电压接得准不准直接影响采样精度；NC 是 No Connect 的缩写，内部什么都没接，属于占位的引脚，跟着手册悬空处理就行。剩下的没点名的，多是同类的多组电源与地，用途可以从名字上直接读出来。

## 六、开发环境与工具链

写代码用一套工具，把程序送进芯片又是另一套东西，分开看更清楚。

STM32 的开发可以选择的集成环境不少，各自定位差别明显。表格里的 IDE 是 Integrated Development Environment 的缩写，译作集成开发环境：

| 工具 | 定位 | 优点 | 缺点 |
| --- | --- | --- | --- |
| VSCode | 代码编辑器 | 界面现代、补全跳转快、插件丰富、方便接 AI | 部分调试场景不如专业 IDE |
| Keil MDK | 集成开发环境 | 兼容性强、资料多、企业常用 | 界面老旧、编辑体验一般 |
| STM32CubeMX | 图形化配置工具 | 可视化配引脚和外设，自动生成初始化代码 | 只管初始化，不管业务逻辑 |
| STM32CubeIDE | ST 官方集成环境 | 基于 Eclipse、免费、编辑体验好 | 企业里用得相对少 |
| IAR EWARM | 老牌集成环境 | 兼容性强、企业常用 | 正版授权贵 |
| CLion | JetBrains 的 C/C++ IDE | 编辑体验一流、有免费社区版 | 搭嵌入式环境比较复杂 |

我采用的是 **Keil MDK + VSCode** 的组合：Keil 负责编译、烧录和调试，VSCode 负责写代码。这样两头的好处都占到了，Keil 那个不太顺手的编辑器基本用不上。

Keil 装起来有三个坑值得先知道：安装路径不能带中文，否则后面会冒出莫名其妙的错误；要和 51 单片机用的 C51 版本 Keil 装在不同目录，三者混在一起会冲突；装完主程序还不算完，还得自己在 Pack Installer 里找到对应的器件支持包 DFP（Device Family Pack）装上，搜 stm32f10 找到对应条目点安装。这个包里放的是这颗芯片的核心固件库和启动文件，没有它工程编译不过。

### 仿真器的选择

程序编译完只是一堆指令，想让它进芯片需要中间人，这个硬件叫仿真器。

市面上常见的几种：ST-Link 是意法官方出的，J-Link 是 SEGGER 出品的业界标准专业调试器，U-Link 主要配 Keil 用，还有我用的 DAP。它们的用法大同小异。

DAP 的正式名字叫 DAPLink，早些年叫 CMSIS-DAP，是 ARM 官方主导维护的开源项目，软件和硬件两方面都开源：GitHub 上能拿到全部固件源码，官方也公开了参考电路设计，所以市面上能买到各种便宜的国产版本，十几块到几十块钱就能入手。相比之下正版的 ST-Link 或 J-Link 动辄上千，初学者没必要。而且 DAP 的用法和 ST-Link 非常像，熟悉了以后换过去几乎没有学习成本。

你可能会问：既然 BOOT0 接高电平就能用串口下载，为什么还要再买个仿真器？因为串口下载只能完成"写进去"这一件事，而仿真器真正的价值是**在线调试**：能在某一行打断点让程序停下来，能单步执行看每一步发生了什么，能实时监视变量的值。写单片机程序，调试占了工作量的大部分，这部分串口完全做不到。

### SWD 接线

目前主流的调试接口是 SWD（Serial Wire Debug，串行线调试），四根线就能跑起来。

先看开发板这一侧，接口就四个脚：

![[STM32/attachments/STM32开发板SWD接口.jpg|开发板上引出的 SWD 接口，丝印分别标着 GND、CLK、DIO、RST]]

仿真器那侧是十针排针，每个脚的功能直接印在外壳上：

![[STM32/attachments/DAP仿真器引脚定义.jpg|DAP 仿真器上的十针排针定义，RST、SWCLK、SWDIO、GND 各自的位置一目了然]]

两边对着丝印连，实际用到的只有四根：

```
  DAP 仿真器              开发板 SWD 接口
  +--------+              +-------------+
  | 1 RST  |--------------| RST         |
  | 2 SWCLK|--------------| CLK         |
  | 4 SWDIO|--------------| DIO         |
  | 5 GND  |--------------| GND         |
  +--------+              +-------------+
        四根杜邦线，一根对一根
```

| 开发板侧 | 仿真器侧 | 作用 |
| --- | --- | --- |
| GND | GND（5 号或 6 号） | 共地，参考电平要一致 |
| CLK | SWCLK（2 号） | 仿真器给目标芯片的时钟，用来同步数据 |
| DIO | SWDIO（4 号） | 双向数据线，命令和数据都走它 |
| RST | RST（1 号） | 复位信号 |

十针里剩下的几根，VREF 用来让仿真器感知目标板的电平，RX 和 TX 是调试器顺带提供的一路串口，还有几个属于更完整的 JTAG（Joint Test Action Group，比 SWD 更早的一套调试接口），跑 SWD 的时候都空着。仿真器排针上有个豁口，那个位置是 5 号脚，数针脚拿它当起点不会错。

上面那张丝印是手头这块 PWLink2 的定义，不同厂家出的 DAP，排针顺序不保证一致，接线前对着自己的仿真器核一遍再插。杜邦线要一根一根接，接错了有可能烧片子。另外 RST 这根其实是可选项，只接 GND、SWCLK、SWDIO 三根也能完成烧录和调试，代价是每次都得手动按一下复位键。

### 编译与烧录流程

硬件接好，剩下的动作都在 Keil 里完成。

代码写完点击工具栏上的 build 按钮，Keil 调用编译器把 C 代码翻译成机器指令。下方的 Build Output 会给出编译结果，Code、RO-data、RW-data、ZI-data 分别对应代码段、只读数据、已初始化的读写数据、未初始化的读写数据各占多少字节，最后那行 `0 Error(s), 0 Warning(s)` 是判断编译是否通过的标志：

![[STM32/attachments/Keil编译输出.png|Keil 的 Build Output 窗口，编译结果显示 0 Error(s)、0 Warning(s)]]

产物落在工程的 MDK-ARM 目录里，其中 `.hex` 结尾的文件就是将来要写进芯片的程序本体，另外还有一批 `.o`、`.d` 结尾的中间文件，属于编译过程的副产品。

烧录之前要先配置调试器。点开魔术棒选项（Options for Target），在 Debug 标签页里把调试方式选成 CMSIS-DAP Debugger，也就是手头这个 DAP：

![[STM32/attachments/Keil烧录配置.png|魔术棒对话框的 Debug 标签页，调试器选择 CMSIS-DAP Debugger]]

配置完成后点工具栏上的 Download 按钮，Keil 就把 `.hex` 里的内容通过 DAP 写进 STM32 内部的 Flash。顺利的话输出窗口会给出 `Flash Load finished` 的提示：

![[STM32/attachments/Keil烧录完成.png|烧录完成后输出窗口给出的 Flash Load finished 提示]]

所谓烧录，就是把编译生成的二进制程序通过仿真器写进 MCU 内置的 Flash，芯片复位后从 Flash 里取指令执行。这套动作是后面每次改完代码都要重走一遍的固定流程。

如果编译时提示缺少 ARM Compiler 5，去魔术棒选项里把编译器改成 version 6 就能解决，新版本的 Keil 默认不再附带旧编译器。

## 七、裸机开发与片上 Flash

最后一节回到一个看着很基础的问题：程序为什么不放在外面，非要塞进芯片里？

软件大概可以分成三层：最上层是应用程序，就是平时说的那些软件；中间层是操作系统，负责统一管理硬件、给应用程序提供运行环境；对于单片机，还有第三种可能，软件既不是应用也不是跑在操作系统上，而是直接跑在硬件本身，这叫**裸机开发**。

裸机的意思是：编译出来的二进制程序直接烧写进 MCU 内部的 Flash，上电之后 CPU 直接从 Flash 里取指令执行，中间没有任何系统层做调度。我目前切入的就是这一层。

看清这一点，回头再看型号里那个 E=512 KB 就顺了。Flash 是存放程序的地方，容量决定了能装下多大的程序；不同容量对应不同规模的产品需求，厂商把 Flash 做成好几档，是为了让各种需求都能买到刚好够用的那一款，把成本压住。这也是为什么 Flash 容量会被直接写进型号。

Flash 之外还有 SRAM，它存的是运行过程中的变量，掉电就清空，和 Flash 是两个完全不同的东西。
