# 引言

前阵子写的一直是 C++ 和数据结构，都在软件世界里打转。类、模板、容器、算法，代码跑在电脑上，摸不到硬件。但我对"程序怎么控制真实世界"这件事一直挺好奇：空调怎么知道温度到了该停机，小车的电机又是怎么转起来的？这些背后都靠一颗小小的芯片在干活，它就是单片机。

所以从这篇开始，我准备正式进入嵌入式和 STM32。第一篇先把从嵌入式到 STM32 这条线理清楚：嵌入式到底特殊在哪，MCU 是什么，ARM 和意法半导体又是什么关系，STM32 那一长串型号该怎么读，以及我打算用什么样的开发环境。

## 一、嵌入式：从通用计算机到专用计算机

计算机这个概念，比我们平时说的"电脑"要广得多。台式机、笔记本是计算机，手机和平板是计算机，服务器是计算机，藏在洗衣机、空调、汽车里那些看不见的芯片，同样是计算机。区别只在于为谁解决什么问题。

| 类型 | 代表 | 主要用途 |
| --- | --- | --- |
| 个人电脑 PC | 台式机、笔记本 | 生产力工具，以后参加工作的"吃饭的家伙" |
| 手机 / 平板 | 智能手机、平板电脑 | 和 PC 共享同一套软件生态，但受生态和形态所限，很难承担生产工具的角色 |
| 服务器 | 机房里的机器 | 支撑 C/S（客户端/服务器）、B/S（浏览器/服务器）结构，核心业务逻辑都在服务端完成 |
| 嵌入式设备 | 空调、手环、汽车电子等 | 藏在设备内部，完成特定控制任务 |

最后一行里的设备，就是嵌入式系统的载体。它和通用计算机的差别，全在那个"嵌"字上。

嵌入式系统是被"嵌"进某个更大的设备里、成为设备一部分的专用计算机。它算不上独立产品，没有人会单独去买"一台嵌入式系统"，你买的是智能空调、是手环、是汽车；嵌入式系统是这些产品内部的"大脑"，是它们实现智能化的内在组件。它藏在设备外壳之内，通常看不见也摸不着，软件和硬件都是为了某个特定任务量身定做的。

功能单一且固定，是它和通用计算机的另一个分野。一台微波炉里的嵌入式系统，使命就是控制面板、定时、设定火力、驱动磁控管，它不会在某个时刻突然变成一个 MP3 播放器。而你的电脑可以一边写文档、一边看视频、一边上网。

这种"嵌入"的特性，带来了一套独特的设计哲学：

- 实时性。汽车刹车踏板被踩下时，嵌入式系统必须在几毫秒内作出反应，"时限"是它的关键指标。
- 资源受限。为了成本和功耗，运算能力、存储空间都非常有限。空调里内置的计算机可能只有几 KB 到几百 KB 内存，而你的电脑是几 GB 甚至几十 GB。
- 低功耗与低成本。智能手表要靠电池供电用很久，产品还要在市场上更有竞争力，功耗和成本都得压到最低。

这两类计算机的分工，可以这样理解：通用计算机是"站出来让你用的"，嵌入式是"蹲在里面替你干的"。

## 二、单片机 MCU 是什么

嵌入式的主角是 MCU。这个缩写展开是 Microcontroller Unit，微控制单元，中文里更常见的叫法是单片机（Single Chip Microcomputer）。

从功能上看，MCU 把处理器（CPU 核心）、存储器（Flash、RAM），以及各种输入输出接口（定时器、ADC、串口等）集成在一起，做成一颗芯片。这里的 ADC 是模数转换器，负责把现实世界的模拟信号（比如电压、温度传感器输出的连续电压）转换成芯片能处理的数字量；串口则是和外部设备收发数据的通道。存储器分两种：Flash 用来存程序，掉电不丢；RAM 用来存运行时的变量，掉电就清空。

从制造上看，是在极纯的硅片上经过光刻、刻蚀、沉积、离子注入等上百道工序，把 CPU、Flash、RAM、ADC、定时器、串口这些模块的电路在硅片上做出来，再用多层金属连线把它们连通，最后切成一颗完整的芯片。

```
+----------------------------------------+
|                MCU 芯片                |
|                                        |
|  +--------+  +--------+  +--------+    |
|  |  CPU   |  | Flash  |  |  RAM   |    |
|  |  核心  |  |  程序  |  |  运行  |    |
|  +--------+  +--------+  +--------+    |
|                                        |
|  +--------+  +--------+  +--------+    |
|  | 定时器 |  |  ADC   |  |  串口  |    |
|  +--------+  +--------+  +--------+    |
+----------------------------------------+
```

所以 MCU 内部除了 CPU，还有一堆别的模块。它已经是一台被集成在同一颗芯片上的微型计算机。

手机芯片和 MCU 的区别，是理解嵌入式的关键。

手机的主芯片是一颗 SoC（System on Chip，片上系统），它把 CPU、GPU、内存控制器、基带等模块集成在同一块硅片上。应用处理器（AP）通常指 SoC 里负责跑应用和操作系统的那部分计算核心。如果硬把手机的主芯片塞进空调，会发生什么：

- 太贵。手机芯片动辄几十美元，而 MCU 只要几毛到几美元。
- 太耗电。手机芯片功耗是瓦级，MCU 是毫瓦甚至微瓦级。同样的电池，换颗芯片可能从能用一年变成只撑一周。
- 太复杂。跑应用处理器需要操作系统、驱动、内存管理，开发难度陡增；而 MCU 不跑系统也能工作，裸机程序（直接操作硬件）几十行代码就能跑起来。
- 没必要。空调不需要处理 2 亿像素的图像，也不需要 5G 基带，多余的算力全是浪费。

还有一点是实时性。空调要解决的是控制问题，不是计算问题：温度到了就停机，遥控按了就响应。这里的"实时"不是"跑得快"，而是**能不能保证在确定的时间内完成**。手机芯片上跑的应用要兼顾很多任务，一个任务什么时候轮到执行并不确定；MCU 通常不跑操作系统，程序直接在硬件上跑，时序更容易预测。当然 MCU 上也能跑 FreeRTOS 这类轻量系统，但"可以不跑"给了它确定的时序基础，这是它在控制场景里不可替代的原因。

MCU 是产业细分之后，一种为低成本实时控制而生的专用计算机。嵌入式里相当一部分工作都属于控制类，这也解释了为什么 MCU 遍地都是，而高端 SoC 只在手机、智能座舱、平板这些高算力场景才会出场。

做 MCU 的厂商不少：恩智浦（NXP）的 LPC 系列、德州仪器（TI）的 MSP430 系列、兆易创新的 GD32 系列、乐鑫（Espressif）的 ESP32 系列（严格说它是带 Wi-Fi/蓝牙的 SoC，习惯上也被归到 MCU 阵营），以及意法半导体（ST）的 STM32 系列。后面我关注的只有 STM32。

## 三、ARM、意法半导体与 STM32 的关系

STM32 由意法半导体生产，但里面的 CPU 内核来自 ARM，这里有一条产业链。

ARM 是一家英国公司（现由软银控股），自己几乎不生产芯片，主要靠卖授权赚钱：它把设计好的 CPU 内核（行业里叫 IP 核，IP 是知识产权 Intellectual Property 的缩写，这里指可以直接授权给别家使用的电路设计成果）授权给芯片公司，由芯片公司集成到自己的芯片里卖出去。高通、联发科、三星、华为海思、紫光展锐的手机芯片，CPU 内核基本都来自 ARM。苹果是个例外，它买的是更底层的架构授权，自研微架构（所以不能简单说苹果的芯片内核"来自 ARM"）。

意法半导体（STMicroelectronics）就是拿到 ARM 内核授权、把它做成标准化芯片，再卖给终端公司的角色。它由意大利的 SGS 和法国的汤姆逊半导体合并而来，总部设在瑞士，中文名取了两国的首字，所以叫"意法"。

再看 ARM 的扩张路线。手机市场爆发是它做大的关键：手机体积小、电池容量有限，对性能和功耗极度敏感，于是产业把 CPU、GPU、内存控制器这些核心模块从"分散在主板上"改成"集成在一块硅片上"，这就是 SoC 的做法，对用户是体验更好，对厂商是成本更低。单一市场的需求总有天花板，ARM 后来又把版图扩到了汽车电子、服务器与数据中心。

手机、汽车、服务器，很多都用 ARM 那套 CPU IP 核。意法半导体做的事，是把它做成面向控制场景的标准化 MCU 芯片，STM32 就是它的 MCU 品牌。

## 四、STM32 名字的由来：ST + M + 32

名字本身最好懂，把 STM32 拆开就是三部分：

![[STM32/attachments/STM32命名拆解.png]]

- ST：意法半导体 STMicroelectronics，也就是前面说的那家欧洲厂商；
- M：微控制器 Microcontroller Unit，也就是 MCU；
- 32：32 位处理器，一次能处理 32 位数据。

这里有个我觉得很贴切的类比：MCU 相当于"手机"，STM32 相当于"华为手机"。STM32 指的不是某一个具体产品，而是一个庞大的产品家族，内部按应用场景分化出了定位不同的子系列。

## 五、STM32 家族与型号命名规则

STM32 家族内部也有系列划分，比较常见的有这几类：

- F0 / F1 / G0：主流型，其中 F0、G0 主打性价比，F1 是最经典的入门系列；
- F4 / H7：高性能型，H7 定位更高，主频可达 480 MHz；
- L0 / L4：超低功耗型，适合电池供电的设备。

入门第一颗芯片通常落在 F1 上。F103 用的内核是 ARM 的 Cortex-M3，也就是前面说的那个从 ARM 授权来的 CPU 核。查资料时会经常撞到 Cortex-M 这个名字，它是 ARM 专门给微控制器设计的一系列内核，常见的有 M0/M0+（低端）、M3（经典）、M4（带浮点）、M7（高性能）。它和 STM32 是"内核"与"整颗芯片"的关系，对应关系大致是：F0/G0 用 M0+，F1 用 M3，F4 用 M4，H7 用 M7。

比起记住系列名，学会读型号其实更有用，因为型号本身就编码了规格。以 STM32F103ZET6 为例：

| 字段 | 含义 | 说明 |
| --- | --- | --- |
| STM32 | 品牌 | 意法半导体的 32 位 MCU |
| F | 系列 | F1 属于基础型 |
| 103 | 子型号 | 增强型系列，F1 里最经典的通用款 |
| Z | 引脚数 | 144 引脚（T=36、C=48、R=64、V=100、Z=144） |
| E | Flash 容量 | 512 KB（6=32K、8=64K、B=128K、C=256K、D=384K、E=512K） |
| T | 封装 | LQFP（H=BGA、T=LQFP、U=VFQFPN） |
| 6 | 温度范围 | -40~85℃，7 是 -40~105℃ |

> 这张表对应的是经典 F1 系列。新系列会在末尾增加更多后缀字段，读到不认识的型号时以官方数据手册为准。

封装指的是芯片的物理外形和引脚引出方式，直接影响能不能手工焊接。LQFP 是四边都有引脚的扁平封装，引脚露在外面，好焊、好飞线；BGA 是焊球阵列封装，引脚做成小焊球排在芯片底部，需要专业设备才能焊，个人调试基本碰不了；VFQFPN 则是更小的无引脚封装，同样不适合手工焊接。选型时这一步容易被忽略，但买到手焊不上去就很尴尬。

这颗就是 STM32F103ZET6 的实物，芯片表面的丝印能直接对上型号：

![[STM32/attachments/STM32F103ZET6实拍.png]]

对照表格反推一遍：F1 基础型、144 个引脚、512 KB Flash、LQFP 封装、工业级温度范围。选型时，这串编码就是第一手信息。

## 六、我的选型和开发环境

选一颗 MCU，我目前会看这几个点：成本和功耗能不能接受，Flash、RAM、引脚数够不够用，需要的外设有没有，以及生态和资料的丰富程度。对新手来说最后一条的权重其实很高，资料多、例程全、社区活跃，遇到问题更容易搜到答案，而 STM32 在这一点上优势明显，F1 系列的 F103 更是典型的"人手一颗"。

真正动手开发需要一套工具链，我打算采用的组合是：

- 硬件：STM32 开发板 + DAP 下载器（DAP 是开源免费的调试器，负责把编译好的程序写进芯片，也能用来在线调试）；
- 软件：Keil MDK（Keil 公司的集成开发环境，MDK 是 Microcontroller Development Kit 的缩写，负责编译和下载代码）负责编译和下载，STM32CubeMX 做图形化配置，HAL 库提供官方驱动；
- 语言：C 语言。

这里的 HAL 是 Hardware Abstraction Layer（硬件抽象层）的缩写。芯片内部有一堆寄存器，直接操作它们要对着几百页手册逐位配置，很容易出错。HAL 库把这些底层操作包装成函数，调用一次 `HAL_GPIO_WritePin()` 就能控制引脚，不用管背后寄存器怎么变。代价是效率略有损失，但对入门来说，先把功能跑通比抠性能重要。

开发流程大致是用 CubeMX 配置好引脚和外设，让它生成初始化代码，再在生成的工程里写自己的业务逻辑，最后用 Keil 编译、通过 DAP 烧录到芯片。这些细节等环境搭起来再细说。
